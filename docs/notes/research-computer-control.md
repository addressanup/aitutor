Legacy CGWindowListCreateImage is deprecated.

Confirmed viable for tutor telestration.

- DaVinci Resolve: Python/Lua scripting API (Resolve→ProjectManager→Project→MediaPool→Timeline→TimelineItem) can create/load projects, import media, build timelines, append/place clips, set clip properties, markers, LUTs/grades, render. ## 1. Computer-use agents now (Aug 2026)

**Anthropic.** Computer use is a beta, **client-side** Anthropic-defined tool: tool type **`computer_20251124`** with beta header **`computer-use-2025-11-24`**, supported on Claude Opus 5, Sonnet 5, Opus 4.8/4.7/4.6, Sonnet 4.6, Opus 4.5 (older `computer_20250124`+`computer-use-2025-01-24` for Sonnet 4.5/Haiku 4.5) — [Anthropic computer-use doc](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool), fetched 2026-08-02. Recommended models: Opus 5 (or Fable 5 at the top tier). Invocation: declare the tool in the Messages API `tools` array (`{"type":"computer_20251124","name":"computer","display_width_px":…,"display_height_px":…,"enable_zoom":true}`) and run the agent loop yourself (or via the SDK tool runner); Anthropic ships a Docker reference environment (Xvfb+Mutter+agent loop). The **Claude Agent SDK has no built-in computer tool** — you'd expose the machine-control layer as a custom/MCP tool. Actions: screenshot, left/right/middle/double/triple click, click-drag, type, key, hold_key, mouse_move, scroll (directional), wait, cursor_position, and **zoom** (full-res inspection of a region). Modifier-held clicks via a `text` param. Resolution guidance: 1080p best balance; 2576px long-edge high-res supported with 1:1 pixel coordinates (~4784 image tokens/screenshot). Built-in prompt-injection classifiers steer the model to ask user confirmation on suspicious screenshots (opt-out via support).

**Latency.** No official per-action figure. Architecture is one model turn per action (screenshot upload + inference) → **estimate 2–6 s per action** on Opus-tier at medium/high effort (basis: single-turn-per-action design + typical Opus token throughput; Opus 5 fast mode, $10/$50, claims up to 2.5× output tps). A 20-action demo is therefore minutes.

**Reliability.** Per leaderboard aggregators ([llm-stats](https://llm-stats.com/benchmarks/osworld-verified), [benchlm](https://benchlm.ai/benchmarks/osworld-verified), Jul–Aug 2026; medium confidence — SEO-adjacent sources): **OSWorld-Verified ~85% frontier** (Claude Fable 5 85.0%, Opus 4.8 83.4%) — above the ~72% human baseline of the original benchmark. The new long-horizon **OSWorld 2.0** ([arXiv](https://arxiv.org/html/2606.29537v1)) is much harsher: Opus 4.8 ~20.6% binary / ~54.8% partial. Read: short scoped GUI tasks are now reliable-ish; multi-step long-horizon sessions are not.

**OpenAI.** Standalone **Operator retired 2025-08-31**; the CUA model lives on inside ChatGPT Agent and the OpenAI Agents SDK computer-use tool. OpenAI's own published OSWorld number for CUA remains 38.1% ([openai.com/index/computer-using-agent](https://openai.com/index/computer-using-agent/)). Anthropic is materially ahead on desktop control.

## 2. macOS control + observation surfaces (stable APIs; from platform knowledge)

**AXUIElement** — read: AXRole/AXSubrole, AXTitle, AXValue, AXChildren, AXFocusedUIElement, AXSelectedText(-Range), positions/sizes of every element; act: `AXUIElementPerformAction` (AXPress, AXShowMenu, AXPick, AXConfirm, AXIncrement/Decrement); write: `AXUIElementSetAttributeValue` on settable attributes (AXValue on text fields/sliders, AXFocused, AXSelectedTextRange, window frame). Electron apps require setting `AXManualAccessibility=true` first. **AXObserver** delivers per-app notifications that amount to a live feed of the learner's actions: `kAXValueChanged`, `kAXFocusedUIElementChanged`, `kAXSelectedTextChanged`, `kAXMenuOpened`/`kAXMenuItemSelected`, `kAXWindowCreated/Moved/Resized`, `kAXTitleChanged`, `kAXUIElementDestroyed`, `kAXApplicationActivated`. This is the semantic observation channel — "learner selected Blade from the Trim menu" without vision-model inference.

**TCC permissions** for a tutor app: **Accessibility** (control + AX reading; prompt sends user to System Settings → Privacy & Security → Accessibility, manual toggle — the scariest ask: "control this computer"); **Screen Recording** (ScreenCaptureKit; manual toggle; macOS 15+ adds recurring ~monthly "is still able to record your screen" re-approval nags); **Input Monitoring** (required to *listen* to keystrokes via event taps — needed for observing typing); **Microphone** (simple in-app allow/deny alert). Prompts fire lazily on first API use; a signed/notarized bundle keeps TCC identity stable. Onboarding must budget for two manual System Settings trips.

**CGEventTap — interrupt-on-learner-input: confirmed.** `CGEventGetIntegerValueField(event, kCGEventSourceStateID)` distinguishes sources: hardware input carries `kCGEventSourceStateHIDSystemState` (1); events the agent posts come from a private `CGEventSource`, and `CGEventSourceSetUserData` lets the agent stamp its own events with a magic number. A listen-only tap (`kCGEventTapOptionListenOnly` at `kCGHIDEventTap`) therefore detects genuine physical input within milliseconds and can pause the demo instantly. (Not cryptographically spoof-proof — fine for UX.)

**ScreenCaptureKit.** `SCContentFilter` does per-display, **per-window**, and include/exclude-app capture; `sourceRect` for region crops; `minimumFrameInterval` up to display refresh (60/120 fps) with scaled output; `SCScreenshotManager` for one-shot grabs; macOS 15 added `SCRecordingOutput` (direct-to-file) and the system `SCContentSharingPicker`. Legacy `CGWindowListCreateImage` is deprecated. Per-window capture means the tutor can watch only FCP, at low fps for token economy.

**Overlay above everything: yes.** An NSWindow/NSPanel with `level = .screenSaver` (or `CGShieldingWindowLevel()`), `ignoresMouseEvents = true`, `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`, `.nonactivatingPanel` draws click-through annotations above other apps' windows **including fullscreen Spaces** — the standard telestration technique (Zoom annotation, screen-drawing apps).

## 3. App-specific control

**Figma.** The plugin API fully supports the blackboard move: `figma.createFrame()/createRectangle()/createEllipse()/createText()` (must `await figma.loadFontAsync` before setting characters), `appendChild`, absolute x/y, fills/strokes, `figma.viewport.scrollAndZoomIntoView()`. FigJam via `editorType: ["figjam"]` adds `createSticky`, `createShapeWithText`, `createConnector` ([developers.figma.com](https://developers.figma.com/docs/plugins/api/api-reference/)). **Private install:** create/import a development plugin via "Import plugin from manifest" in the desktop app — no review, runs locally immediately; org-private publishing exists (plus `enablePrivatePluginApi` for private-only APIs). Plugins are sandboxed with no official external IPC, but the plugin's UI iframe can hold a **WebSocket to a localhost server** — the established bridge pattern (talk-to-Figma MCP tools) that lets the tutor agent script the canvas live. Gap: a plugin can't launch Figma or open a file — that first step needs app-level automation (AX/keystrokes). REST API can't draw on canvas.

**Final Cut Pro.** AppleScript support is **minimal — confirmed**: essentially the standard suite (activate, open); no timeline object model. **FCPXML** (v1.13 with FCP 11) is the state interchange: expresses libraries/events/projects, formats/assets/effects, the spine, asset-clips, gaps, transitions, markers, keywords, roles, and many adjustments; export→modify→import round-trips, but import creates *new* project items rather than mutating the open timeline in place — good for "here's a prepared exercise timeline," not for live edits. **CommandPost** ([commandpost.fcp.cafe](https://commandpost.fcp.cafe/)) proves deep live control is possible: it's a Lua (Hammerspoon-derived) app that walks **FCP's rich accessibility tree** plus posts keystrokes/menu commands and reads FCP's preferences/command-set files, exposing hundreds of actions (and AppleScript bindings). That same AX richness serves the tutor's *observation* side. **Keyboard-shortcut injection is a viable channel**: FCP's Command Editor maps hundreds of commands to arbitrary keys; install a known command set and drive edits deterministically via CGEvents — exactly how CommandPost and hardware control surfaces work.

**DaVinci Resolve.** Built-in scripting API (Python 3/Lua): `Resolve → ProjectManager → Project → MediaPool → Timeline → TimelineItem` — create/load projects, import media, build timelines from clips, append/insert clips, read/write timeline item properties (transforms, versions, LUTs/CDL, markers), manage render queue, trigger renders and Fusion. **Free-version limitation (load-bearing):** since **Resolve 19.1 (Nov 2024)** external scripting (`DaVinciResolveScript` from another process) is **Studio-only ($295)**; the free edition runs scripts only from the internal Console, and UIManager GUIs are also Studio-only ([unofficial API docs](https://deric.github.io/DaVinciResolve-API-Docs/), [pulseedit](https://pulseedit.com/davinci-resolve-19-scripting-api-fix.html)). So Resolve offers the *best* first-party automation surface of the three apps — but only for Studio owners; free-tier learners fall back to AX + keystrokes like FCP.

## 4. Genuinely new, 2025–2026

- **Windows 11 Agent Workspace** (Insider, Nov 2025→2026): OS-native agent runtime — agents get a separate contained Windows session + account, scoped known-folder permissions, off-by-default admin toggle ([windowscentral](https://www.windowscentral.com/microsoft/windows-11/microsoft-just-revealed-how-windows-11-is-evolving-into-an-agentic-os-finally-the-explanation-weve-all-been-waiting-for)). First OS to productize agent isolation.
- **Apple: no macOS agent runtime.** macOS Tahoe 26 expands **App Intents** (Spotlight actions, Shortcuts automations, on-device model access) and 26.4 is expected to ship the personalized-Siri App Intents wave — but these are app-declared verbs, not free-form machine control. Third-party macOS agents still ride Accessibility + ScreenCaptureKit + CGEvents; no sign of TCC restricting that path.
- **Reliability techniques now standard:** accessibility-tree/DOM grounding and **Set-of-Marks** (numbered overlay labels on interactable elements) to replace brittle pixel-coordinate clicking; the `zoom` action for small UI; **verifier loops** (Anthropic's own docs prescribe screenshot-after-each-step self-checks and keyboard shortcuts over fiddly widgets); instruction-before-image ordering for click accuracy. OSWorld 2.0 exists precisely because short-task scores saturated (~85%) while long-horizon reliability remains ~20–55%.

## Implications for a tutor that must demonstrate reliably and observe a learner

1. **Don't run demos on raw pixels.** The winning stack is hybrid: AX tree for grounding and element targets, keyboard-shortcut/command channels (FCP command sets, Figma plugin bridge, Resolve API where Studio) for deterministic actions, vision only as fallback/verification. This converts a ~85%-per-episode probabilistic actor into a mostly deterministic one — essential because a tutor demo that misclicks *teaches the wrong thing*.
2. **Observation is nearly free and semantic.** AXObserver notifications + a listen-only CGEventTap give real-time "learner did X" events without burning vision tokens; per-window ScreenCaptureKit at low fps + zoom covers what AX can't see (FCP's viewer/timeline canvas).
3. **Interrupt-on-touch is trivially implementable** via `kCGEventSourceStateID` — the learner-in-control principle has a concrete, millisecond-latency mechanism.
4. **The overlay blackboard is proven tech** (screenSaver-level click-through window over fullscreen apps) — telestration, callouts, and Set-of-Marks labels can share one surface.
5. **Latency budgets the pedagogy:** at ~2–6 s/action, demonstrations must be narrated (voice fills the gaps) and pre-planned via the deterministic channels; pure model-driven improvisation is too slow and too fallible for long sequences (OSWorld 2.0).
6. **Permissions are a first-run UX problem:** two manual System Settings toggles (Accessibility, Screen Recording) plus Input Monitoring and mic — the onboarding must teach the learner why each is needed, which conveniently doubles as the product's trust story.
7. **App choice matters:** Figma (private plugin + WebSocket) and FCP (AX-rich + command sets, proven by CommandPost) are tractable; Resolve free-tier lost external scripting in 19.1, so a Resolve pivot either assumes Studio or degrades to the FCP-style AX/keystroke stack.

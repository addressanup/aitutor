## 1. Realtime conversational voice options (verified Aug 2026)

**OpenAI Realtime API (gpt-realtime-2.1 / -mini).** True speech-to-speech, WebRTC/WebSocket, native server-VAD barge-in with response truncation. Typical time-to-first-audio ~250ms; 2.1 claimed >=25% lower p95 latency vs prior gen (theplanettools/tokenmix, 2026). Price: $32/M audio input tokens, $64/M audio output, cached audio input $0.40/M (80x discount); mini $10/$20. Tokenization: user audio 1 tok/100ms, assistant 1 tok/50ms (layer3labs, aireiter, 2026). Real-world (4,000-session study, HackerNoon 2026): ~$0.05/min with aggressive prompt caching, $0.18–0.46/min uncached — context regrowth, not raw audio, is the cost driver. Expressive, best-in-class prosody; Nepali is not a supported strength (low-resource languages weak in speech-native models generally).

**Google Gemini Live (gemini-3.1-flash-live-preview).** Native audio, WebSockets, built-in VAD/interruption handling, proactive audio. Verified from ai.google.dev pricing page (fetched 2026-08-02): audio input $3.00/M tok ($0.005/min at 32 tok/s), audio output $12.00/M ($0.018/min at 25 tok/s), text in/out $0.75/$4.50, image/video input $1.00/M ($0.002/min) — note the video-input line matters: Gemini Live can *watch the learner's screen* in the same session, directly relevant to the OBSERVE loop. Cheapest full speech-to-speech by ~10x vs OpenAI on output audio. Still "preview"-labeled; session-length limits and preview churn are the operational risk.

**ElevenLabs Agents.** Cascaded platform (Scribe realtime STT ~150ms + LLM of choice + Flash v2.5 TTS ~75ms model TTFB); sub-second turn latency, barge-in supported. Billed per **wall-clock conversation minute**: ~$0.08/min (annual business) to ~$0.10–0.12/min (Creator/Pro/premium tiers); silence accrues cost (cloudtalk, cekura, 2026). Highest voice quality; worst billing shape for tutoring, where the tutor talks maybe 30% of a session and long silent practice stretches are the point.

**Cartesia.** TTS latency leader: Sonic-3 ~90ms TTFA, Sonic Turbo ~40ms; 42 languages incl. Hindi, **no Nepali** (cartesia.ai, texttolab, 2026). TTS ~$5–37/M characters by plan (Pro from ~$4–5/mo, Scale $299/mo). "Line" agent platform (Sonic + Ink STT): $0.06/min, $0.014/min at Scale (eesel, 2026). Best pick as the low-latency TTS *component* in a cascaded stack for English/Hindi.

**Deepgram.** Nova-3 streaming STT $0.0077/min; Flux adds conversational turn-detection; Aura-2 TTS $0.030/1K chars but ~7 languages, zero subcontinent coverage; bundled Voice Agent API ~$4.50/hr (diyai, texttolab, dynalord, 2026). Strong cheap STT component; irrelevant for Nepali TTS.

**Anthropic.** **No developer voice API exists as of Aug 2026.** Claude voice mode (consumer apps) is a cascaded ElevenLabs TTS pipeline, turn-based not duplex; model choice (Opus/Sonnet/Haiku) added 2026-07-23 (TechCrunch); Claude Code shipped push-to-talk voice dictation 2026-03-03 (TechCrunch). Implication: if Claude is the computer-use brain (likely, given its computer-use lead), the voice layer is necessarily third-party and cascaded — which is fine, and is the architecture mixed-language support forces anyway.

## 2. Local/on-device on Apple Silicon

**STT.** Apple SpeechAnalyzer/SpeechTranscriber (macOS 26): best on-device accuracy measured — WER 2.12% clean / 4.56% noisy vs Whisper's 9.02%/16.25%, ~3x faster than Whisper Small, Neural Engine-native, effectively free and private (MacRumors 2025-06-18; get-inscribe/vocai 2026). Limits: one language per session, no code-switching, no Nepali. Parakeet TDT 0.6B (MLX): ~6x faster than Whisper large-v3 pipelines, near-instant push-to-talk latency, English-only. whisper.cpp/mlx-whisper large-v3: 2–3x realtime on Metal, 99 languages, handles code-switching — still the multilingual local pick, but Nepali WER is mediocre.

**TTS.** Kokoro-82M: several-x realtime even on CPU, 8 languages, good-not-great naturalness; Chatterbox Multilingual: 23-language cloning; Qwen3-TTS claims 97ms end-to-end streaming (vendor system figure, not Mac-verified); mlx-audio wraps TTS/STT/STS on MLX (ocdevel, localaimaster, murmurtts, 2026). None of these has credible Nepali.

**Verdict.** A local-first loop (SpeechAnalyzer or Parakeet + Kokoro) is *viable today* for an English-language tutor: sub-300ms STT, sub-500ms TTS start, $0 marginal COGS, strong privacy story that matches the constitution's trust principle. It is **not viable for Nepali/mixed-language** — no quality local Nepali TTS exists in Aug 2026. Sane posture: local pipeline as the English/privacy tier, cloud for Indic languages.

## 3. Mixed-language / Nepali / Hinglish — honest assessment

**Nepali TTS** (production field test, kchakhabar.com, bishal.io 2026): ElevenLabs Multilingual v3 = excellent Nepali pronunciation, $0.30–0.40/min — the quality ceiling. Gemini 3.1 Flash TTS (Aoede) = comparable to ElevenLabs "with a few quirks" at ~$0.03/min ($20/M audio tokens) — the author switched for a 10x saving. Azure ne-NP (HemkalaNeural/SagarNeural, added late 2024) = works, below ElevenLabs quality, ~$0.04/min ($15/M chars). Deepgram/Cartesia = **no Nepali at all**.

**Nepali STT:** ElevenLabs Scribe places Nepali in its 5–10% WER band — respectable but well below its 3.1% FLEURS headline average (elevenlabs.io, 2026). Whisper large-v3 Nepali is usable but error-prone on names/technical vocabulary. **Sarvam AI** (Saaras v3) explicitly lists Nepali among its 22 Indian languages, has a dedicated Nepali STT API page, streams at <150ms time-to-first-token, and — critically — is trained for **code-mixing** (docs.sarvam.ai, sarvam.ai/apis/speech-to-text/nepali, 2026). Pricing ~Rs.30/hr STT (~$0.35/hr est.), Bulbul v3 TTS Rs.15–30/10K chars with native Hinglish code-switch synthesis, 35+ voices, sub-250ms streaming. Caveat: Bulbul's polished voice set covers ~11 languages; Nepali TTS voice quality from Sarvam needs hands-on validation before committing.

**Hinglish (proxy):** Sarvam is purpose-built for it (STT and TTS both handle mid-sentence Hindi/English switching); Cartesia and ElevenLabs handle Hindi well; gpt-realtime handles Hindi conversationally but degrades on heavy code-switching; Azure hi-IN is broad but mid-tier natural.

**Honest weak spots:** (a) no speech-to-speech model (OpenAI/Gemini native audio) is *strong* in Nepali — mixed-language tutoring forces a cascaded architecture; (b) Nepali technical vocabulary (FCP terms, English jargon embedded in Nepali sentences) is exactly the hard case for every STT listed — expect a custom-vocabulary/keyword-boosting layer; (c) no local Nepali option, so the privacy tier is English-only for now.

## 4. Architecture notes

**Narrate-while-acting: yes, cleanly.** Two-plane design: an action plane (computer-use model executing clicks/keystrokes) emits structured step events; a narration plane (small fast LLM -> streaming TTS via Cartesia/Gemini) consumes events and speaks over them. TTS streams are independently cancellable, so learner barge-in kills narration audio (<300ms) without aborting the in-flight action — the executor can be paused at the next safe step boundary. No vendor prevents this; it's client-side orchestration (LiveKit Agents / Pipecat are the standard frameworks; Sarvam ships a LiveKit plugin). Speech-to-speech APIs (gpt-realtime, Gemini Live) can also drive tools mid-speech, but coupling voice and action in one model loop makes barge-in ambiguous (does interrupting speech interrupt the click?) — keep planes separate.

**Latency budget.** Human inter-turn gap median ~200ms (Stivers et al. 2009). Targets: barge-in acknowledgment (audio duck/stop) <300ms — hard requirement; backchannel/simple replies <800ms voice-to-voice; substantive tutoring answers 1–1.5s acceptable if masked with continuers ("okay, so—"); >2s reads as broken. Tutoring is more forgiving than call-center voice because pedagogical pauses are natural, but *interruption responsiveness* is where tutor trust lives.
